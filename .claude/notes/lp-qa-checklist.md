# LP納品前チェックリスト

出典: 金子知也さん「AI活用でUIの定量評価やってみた」
https://note.com/kaneko_design/n/n456aab2d77f1
元の86項目チェックリスト（Claude Artifact、閲覧自由）:
https://claude.ai/code/artifact/e2fd2610-bab7-48fa-a458-a68594d55f98

元記事はコンポーネント設計25項目・ユーザビリティ32項目・アクセシビリティ29項目の
計86項目。複雑なプロダクトのUI/UX向けなので、1〜2ページのLP制作の規模には
そのままでは重すぎる。ここでは実際に使う分だけを抜き出している。

案件を受けたら、納品前にこのリストで一通り確認する。

## アクセシビリティ（WCAG 2.1 AAベース）

- [ ] すべての画像に alt 属性がある（意味のない装飾画像は alt=""）
- [ ] 本文と背景のコントラスト比が 4.5:1 以上
      （大きい見出し文字は 3:1 以上でも可）
- [ ] header / nav / main / footer のランドマーク構造がある
- [ ] リンクやボタンに :focus-visible のアウトラインがある
      （キーボード操作でどこにいるか分かる）
- [ ] フォームがある場合、input に対応する label がある

## コンポーネント・レイアウト

- [ ] ボタンの見た目が全ページで統一されている（色・角丸・余白）
- [ ] 見出し(h1〜h3)の階層が飛んでいない
- [ ] リンク・ボタンのタップ領域が指で押しやすい大きさ（目安44px角）
- [ ] フォーム・CTAが迷わない位置にある

## ユーザビリティ（ニールセンの原則から実用分だけ）

- [ ] いま何のページか、開いた瞬間に分かる（h1・ファーストビュー）
- [ ] 次に何をすればいいかが常に1つに絞られている（CTAが競合していない）
- [ ] エラー・入力ミス時に、何が悪いか分かるメッセージが出る
- [ ] 一貫した言葉遣い（「送信」と「送る」を混在させない等）

## 動作確認（自分のスクリプトで機械的に）

- [ ] 320〜1440px の主要幅で横スクロールが出ない
- [ ] 全内部リンクが 200 を返す（リンク切れがない）
- [ ] コンソールエラー・リクエスト失敗がない
- [ ] 日本語の改行が単語・複合語の途中で切れていない
      （`tools/wrap-ja.py` があるプロジェクトならそれを流す）

## 使い方の注意

- このチェックリストを通したことを、クライアントへの営業文句にするのは
  実際に運用してから。「品質チェック済み」は事実であることが前提。
- 元記事のスコア化ロジック（得点÷満点×100）は、複数案件を継続して
  比較したくなったら導入を検討する。いまの案件数ではまだ早い。
